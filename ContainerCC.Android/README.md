# ContainerCC для Android

Те же контейнеры `.cc`, что открывает плагин `ContainerCC.wcx64` в Total Commander, но прямо на
телефоне: просмотр, извлечение, добавление, удаление, уплотнение и проверка целостности.
Компьютер в работе не участвует — контейнер лежит в общей памяти телефона и меняется на месте.

Логика формата не переписана: приложение, командная строка и WCX-плагин ссылаются на один проект
`Container.Core` (net10.0, без зависимости от Windows). Контейнер, упакованный на телефоне, читается
плагином на Windows, и наоборот — это проверяется отдельно (см. «Открыть чужой контейнер» ниже).

## Что умеет

| Действие | Где в приложении |
|---|---|
| Открыть контейнер как папку | нажать на файл `.cc` |
| Посмотреть содержимое | список, переход по папкам, первая строка списка «.. (выше)» |
| Извлечь выбранное | Действия → «Извлечь выбранное…» (с отчётом по файлам и кнопкой СТОП) |
| Извлечь всё | Действия → «Извлечь всё…» (быстрее: каждый чанк читается один раз, но без остановки) |
| Добавить файл или папку | отметить в списке файлов телефона → Действия → «Добавить выбранное в открытый контейнер» |
| Создать новый контейнер | в списке файлов телефона: Действия → «Упаковать выбранное в новый .cc» |
| Удалить файл или папку внутри контейнера | отметить → Действия → «Удалить выбранное» (папка уходит с содержимым) |
| Удалить по маске | Действия → «Удалить по маске…» («*.log», «docs\*.*»; маска без разделителя относится к тому, что видно в списке; перед удалением показывается, что именно попадёт под маску) |
| Освободить место после удалений | Действия → «Уплотнить контейнер (compact)» |
| Проверить целостность | Действия → «Проверить выбранное» (хэш чанков + декомпрессия, без записи на диск) |
| Свойства и состояние | Действия → «Свойства контейнера» (чанк, уровень, мёртвые чанки, сколько освободит compact) |
| Удалить контейнер с телефона | в списке файлов телефона: отметить один или несколько `.cc` → Действия → «Удалить» → подтверждение «Вы уверены? Да / Нет». Убираются сами контейнеры и их резервные копии `.cc.bak`. Если хотя бы один отмеченный объект не контейнер (файл или папка), показывается окно с объяснением и не удаляется ничего |

Отметка и открытие — короткое и долгое нажатие:

- папка — и в списке телефона, и внутри контейнера: короткое — войти, долгое — отметить;
- `.cc` в списке телефона: короткое — открыть контейнер, долгое — отметить (именно так `.cc`
  отмечается, чтобы его удалить);
- обычный файл телефона: короткое — отметить, долгое — открыть тем приложением, которое на телефоне
  назначено для такого типа (`.txt` — текстовой программой, `.jpg` — галереей, `.pdf` — читалкой).
  Файл передаётся другой программе только на чтение; если такой программы нет, приложение говорит
  об этом;
- файл внутри открытого контейнера: долгое нажатие работает так же. Файла на диске внутри контейнера
  нет, поэтому он сначала извлекается во временную папку в кэше приложения (имя и папки внутри
  контейнера сохраняются — читалке нужно расширение), и уже потом открывается той же программой.
  Перед каждым новым открытием временная папка очищается. Отмечается такой файл коротким нажатием
  (вложенный `.cc` — тоже коротким).

Кнопки вверху: НАСТРОЙКИ, ОБНОВИТЬ, ВЫДЕЛИТЬ, ДЕЙСТВИЯ (и СТОП, когда идёт долгая операция).
Кнопки «выше» больше нет — переход наверх делает первая строка списка «.. (выше)».
Аппаратная кнопка «Назад» и жест возврата поднимают на уровень вверх тем же путём: по папкам
телефона, а внутри контейнера — по папкам контейнера и наружу. Уже на корне общей памяти
приложение уходит на рабочий стол (отходит на задний план), а не закрывается. Выше общей памяти
приложение не ходит: там только системные монтирования, строка «.. (выше)» на корне отвечает
«Вы уже в корне общей памяти». Подсказка при этом показывается один раз: несколько нажатий «вверх»
подряд её не повторяют, она может появиться снова не раньше, чем через восемь секунд.

## Настройки

| Настройка | Что делает |
|---|---|
| Фильтр по расширению | список файлов телефона: «все файлы» (по умолчанию) или «только контейнеры .cc». При фильтре остаются папки (без них некуда идти) и `.cc`; прочее — обычные файлы, архивы и резервные копии `.cc.bak` — скрыты. На содержимое уже открытого контейнера не влияет. Отметки в списке файлов телефона при смене фильтра сбрасываются, чтобы скрытое не участвовало в операциях; внутри контейнера отметки остаются |
| Тема | как в системе (по умолчанию), светлая, тёмная. Применяется сразу, экран перечитывается |
| Новый контейнер — уровень сжатия | 1..22, по умолчанию 3. Чанки уже созданного контейнера сжимаются тем уровнем, что записан в его заголовке — настройка их не меняет |
| Новый контейнер — размер чанка | 64 КБ, 128 КБ, 256 КБ, 512 КБ, 1 МБ (по умолчанию), 2 МБ, 4 МБ, 8 МБ, 16 МБ — границы, которые допускает формат. Больший чанк упаковывает быстрее и занимает меньше места в индексе, меньший удобнее при выборочном извлечении |

Уровень и размер чанка влияют только на новые контейнеры: они лежат в заголовке готового контейнера,
и добавление в него берёт их оттуда.

## Сборка

Нужны .NET SDK с workload `android`, Android SDK и JDK 17+ (`dotnet workload install android`).

```powershell
$env:AndroidSdkDirectory = 'C:\Program Files (x86)\Android\android-sdk'
$env:JdkSdkDirectory     = 'C:\Program Files\Android\openjdk\jdk-21.0.8'
dotnet build ContainerCC.Android\ContainerCC.Android.csproj -c Release
```

APK: `ContainerCC.Android\bin\Release\net11.0-android\com.containercc-Signed.apk` (около 15 МБ,
подписан отладочным ключом — для установки своим устройствам этого достаточно).

## Установка и запуск

```powershell
$adb = 'C:\Program Files (x86)\Android\android-sdk\platform-tools\adb.exe'
& $adb install -r -g ContainerCC.Android\bin\Release\net11.0-android\com.containercc-Signed.apk
```

Разрешение «Доступ ко всем файлам» нужно, чтобы контейнеры лежали в общих папках — там же, где их
видит Total Commander для Android. Вручную: Настройки → Приложения → ContainerCC → «Разрешения» →
«Доступ ко всем файлам». При первом запуске приложение само предлагает открыть этот экран.
Через adb: `adb shell appops set com.containercc MANAGE_EXTERNAL_STORAGE allow`.

Имя активности для `am start` берётся из `ContainerCC.Android\obj\Release\net11.0-android\AndroidManifest.xml`
(вид `crc64…​.MainActivity`, меняется при переименовании классов).

### Если телефон Xiaomi/Redmi/POCO (MIUI)

adb-установка на MIUI по умолчанию блокируется с ошибкой
`INSTALL_FAILED_USER_RESTRICTED: Install canceled by user`. Нужно один раз включить
«Настройки → Для разработчиков → Установка через USB» (MIUI спросит аккаунт Xiaomi и интернет);
после этого команда установки выше проходит обычным порядком.

Без этого APK можно положить в память телефона и открыть в «Проводнике»:

```powershell
adb push ContainerCC.Android\bin\Release\net11.0-android\com.containercc-Signed.apk /storage/emulated/0/Download/ContainerCC.apk
```

При первом открытии «Проводник» попросит разрешить установку неизвестных приложений для себя —
разрешение нужно только на время установки. Подпись отладочная: приложение ставится из файла,
как любое другое, и обновляется той же командой `adb install -r`.

## Проверки на устройстве

Полная проверка формата на Android (упаковка → распаковка деревом → добавление → удаление папки →
уплотнение → проверка целостности), результат в журнале устройства:

```powershell
adb shell am start -n "com.containercc/<activity>" --es selftest 1
adb logcat -d -s ContainerCC:V
```

Открыть контейнер, созданный на Windows (CLI или плагином), распаковать его на телефоне и проверить:

```powershell
adb push .harness\test.cc /storage/emulated/0/Download/test-win.cc
adb shell am start -n "com.containercc/<activity>" --es open /storage/emulated/0/Download/test-win.cc
```

## Ограничения, о которых стоит знать заранее

- Android 7.0 (API 24) и выше; минимальная версия задана в `SupportedOSPlatformVersion`.
- Извлечение сохраняет пути записей контейнера: `src\docs\a.txt` окажется в `выбраннаяпапка\src\docs\a.txt`,
  как и «Extract» в Total Commander.
- Остановка длинной распаковки возможна между файлами, а «Извлечь всё» — одна операция без остановки:
  так каждый чанк читается один раз.
- Отменённое добавление не оставляет в контейнере ничего: дописанные до остановки чанты отсекаются,
  файл возвращается к прежней длине. На устройстве это проверяется побайтово (`SELFTEST PASSED`).
- Перед операцией приложение оценивает, сколько нужно места, и предупреждает, если его не хватает.
- Резервная копия `.cc.bak` делается для контейнеров до 100 МБ — то же правило, что у плагина.
- `zstd` в ядре — чистый C# (ZstdSharp): распаковка быстрая, упаковка на телефоне медленнее, чем на ПК.
